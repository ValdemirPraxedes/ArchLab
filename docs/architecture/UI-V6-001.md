# UI-V6-001 — Ícones e identidade visual de componentes de dados (v0.6)

> **Status:** proposta de especificação de design para revisão no PR de planejamento v0.6. Não autoriza implementação.
> **Base:** [UI-V5-001](UI-V5-001.md) e `frontend/src/features/editor/ComponentIcon.tsx`.
> **Biblioteca:** `lucide-react`, já usada no frontend. Confirmar nomes exportados na versão instalada/lockfile antes da implementação.

## 1. Padrão obrigatório

- Adotar somente ícones **Lucide React** na paleta, canvas React Flow, seletor de tipo e painéis onde um componente for representado.
- Preservar padrão v0.5: `size={22}`, `strokeWidth={1.8}`, SVG decorativo `aria-hidden="true"`, rótulo textual legível e cores herdadas do tema.
- O `type` determina o ícone via mapa tipado `Record<ComponentType, IconComponent>`; não adicionar `icon` ao payload de arquitetura.
- Diferenciar tipos por silhueta e texto, sem depender apenas de cor; observar zoom e temas claro/escuro.
- Não substituir nem duplicar ícones já definidos para `CACHE`, `OBJECT_STORAGE`, `SEARCH_ENGINE`, serviços, clientes e `BROKER`.
- Não utilizar logotipos de fornecedores (PostgreSQL, MongoDB, Redis, Snowflake, Kafka etc.): os nós representam categorias técnicas, não produtos.

## 2. Bancos e armazenamento — 8 ícones novos

| Tipo canônico | Nome na paleta | Lucide React | Classe esperada | Motivo |
| --- | --- | --- | --- | --- |
| `RELATIONAL_DATABASE` | Relational Database | `Table2` | `lucide-table-2` | tabela/linhas e colunas |
| `DOCUMENT_DATABASE` | Document Database | `FileJson2` | `lucide-file-json-2` | documento estruturado JSON |
| `KEY_VALUE_STORE` | Key-Value Store | `KeyRound` | `lucide-key-round` | acesso direto por chave |
| `COLUMN_FAMILY_DATABASE` | Column-Family Database | `Columns3` | `lucide-columns-3` | armazenamento orientado a famílias de colunas |
| `GRAPH_DATABASE` | Graph Database | `GitFork` | `lucide-git-fork` | nós e relacionamentos |
| `TIME_SERIES_DATABASE` | Time-Series Database | `Clock3` | `lucide-clock-3` | registros organizados temporalmente |
| `DATA_WAREHOUSE` | Data Warehouse | `Warehouse` | `lucide-warehouse` | repositório de dados analíticos |
| `DATA_LAKE` | Data Lake | `Waves` | `lucide-waves` | conjuntos heterogêneos de dados |

**Observação:** `DATA_WAREHOUSE` e `DATA_LAKE` permanecem diferentes de `OBJECT_STORAGE`; `KEY_VALUE_STORE` não deve reutilizar o símbolo `DatabaseZap` de `CACHE`.

## 3. Processamento de dados e integração — 7 ícones novos

| Tipo canônico | Nome na paleta | Lucide React | Classe esperada | Motivo |
| --- | --- | --- | --- | --- |
| `ETL_PIPELINE` | ETL Pipeline | `ListFilter` | `lucide-list-filter` | estágios conectados de extração, transformação e carga |
| `DATA_TRANSFORMER` | Data Transformer | `Replace` | `lucide-replace` | transformação de valores |
| `BATCH_PROCESSOR` | Batch Processor | `Boxes` | `lucide-boxes` | processamento em lotes |
| `STREAM_PROCESSOR` | Stream Processor | `RadioTower` | `lucide-radio-tower` | fluxo contínuo de eventos lógicos |
| `DATA_INGESTION` | Data Ingestion | `CloudDownload` | `lucide-cloud-download` | recebimento de dados de fontes externas simuladas |
| `DATA_QUALITY_VALIDATOR` | Data Quality Validator | `ClipboardCheck` | `lucide-clipboard-check` | verificação e validação |
| `CDC_CONNECTOR` | CDC Connector | `GitCompareArrows` | `lucide-git-compare-arrows` | captura de mudanças e diferenças |

**Nota sobre ETL:** `ListFilter` foi selecionado para diferenciar o pipeline do ícone `Workflow` já usado por `ORCHESTRATOR_SERVICE` na v0.5. Validar o export na versão instalada.

## 4. DATABASE genérico — legado, não criável

- `DATABASE` mantém o antigo `Database` **apenas para leitura de um arquivo histórico na prévia de importação**, se necessário.
- Depois de migração explícita válida para `RELATIONAL_DATABASE`, o canvas e a paleta exibem `Table2`.
- `DATABASE` não aparece na paleta v0.6, no seletor de criação ou no JSON canônico exportado.
- Caso a migração dependa de escolha humana, não alterar o ícone até confirmar e validar a conversão.
- Nunca trocar o ícone como substituto para migração semântica real.
