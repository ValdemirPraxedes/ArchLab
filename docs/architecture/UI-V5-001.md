# UI-V5-001 — Ícones e identidade visual dos componentes ArchLab v0.5

> **Status:** especificação de design para implementação frontend (sem alteração de componentes React nesta branch).  
> **Biblioteca:** `lucide-react` já instalada no frontend (`^0.468.0`).  
> **Referência de implementação atual:** `frontend/src/features/editor/ComponentIcon.tsx` e `ComponentIcon.test.tsx`.  
> **Decisão de produto:** `API` não é mais um componente da paleta v0.5; o nó genérico passa a ser `SERVICE`. Ver [MIG-V5-001](../api/MIG-V5-001.md).

## 1. Regra visual

- Usar **Lucide React**, não imagens externas nem emojis como ícones oficiais.
- O mesmo ícone deve aparecer na paleta, no nó React Flow, no seletor de tipo e em demais lugares que representam o componente.
- Preservar ícones e estilo dos tipos preexistentes: tamanho de referência 22px, `strokeWidth=1.8`, SVG decorativo com `aria-hidden=true`. Rótulo acessível continua no texto.
- Ícones de aparência semelhante devem manter identidade reconhecível em tamanhos pequenos, sem depender exclusivamente de cor.
- A cor é responsabilidade da categoria/tema claro ou escuro; não definir uma cor fixa por ícone no componente.
- `API` só é reconhecido temporariamente no processo de importação; **não** mostrar esse tipo na nova paleta.

## 4. Implementação esperada — frontend

Manter o padrão já usado por `ComponentIcon.tsx`: mapa tipado `Record<ComponentType, IconComponent>` com imports explícitos de `lucide-react`.

```tsx
// Exemplo ilustrativo de adições à tabela de ícones — não substitui o arquivo completo.
const v5Icons = {
  SERVICE: Server,
  API_GATEWAY: Route,
  BFF: Layers3,
  WORKER: Cog,
  SCHEDULER: CalendarClock,
  AUTHENTICATION_SERVICE: ShieldCheck,
  WEBHOOK_RECEIVER: Webhook,
  ORCHESTRATOR_SERVICE: Workflow,
  INTEGRATION_BUS: Cable,
  CACHE: DatabaseZap,
  OBJECT_STORAGE: HardDrive,
  NOTIFICATION_SERVICE: BellRing,
  SEARCH_ENGINE: Search,
  SERVICE_REGISTRY: Waypoints,
  RULES_ENGINE: ListChecks,
} as const;
```

Não implementar imports no backend, OpenAPI ou simulador: ícone é apresentação frontend. Não armazenar nome de ícone no JSON da arquitetura, pois o componente pode ser serializado apenas por `type` e `displayName`.

## 5. Critérios de aceitação UX e testes

- **UI-5-ICON-01:** os 15 novos tipos possuem ícone Lucide explícito, exibido na paleta e no canvas.
- **UI-5-ICON-02:** `SERVICE` possui `Server`; `API` não aparece como opção criável.
- **UI-5-ICON-03:** todos os nove componentes preexistentes preservam seus SVGs atuais.
- **UI-5-ICON-04:** selecionar, mover, editar e executar simulação não muda a identidade visual do nó.
- **UI-5-ICON-05:** cada SVG decorativo mantém `aria-hidden=true`; label textual permanece acessível.
- **UI-5-ICON-06:** testar `svg.lucide-*` com parametrização por `ComponentType` (incluindo novos tipos), seguindo o padrão de `ComponentIcon.test.tsx`.
- **UI-5-ICON-07:** legibilidade verificada em temas claro/escuro e tamanhos usuais de zoom do React Flow.
- **UI-5-ICON-08:** ícone não é usado para inferir protocolo ou comportamento de Actions; `type` e capabilities mantêm-se como fonte de verdade.

## 6. Exclusões

`LOAD_BALANCER` e `CDN` não recebem ícones de paleta na v0.5: estão reservados à futura expansão de infraestrutura. A lista não inclui `API` como componente criável. Não criar assets gráficos adicionais nem ícones específicos de fornecedor (Redis, S3, IBM, Elastic etc.).
