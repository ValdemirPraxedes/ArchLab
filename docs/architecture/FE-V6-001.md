# FE-V6-001 — Planejamento frontend v0.6: banco de dados e ETL

> **Status:** especificação para implementação futura; não representa UI já implementada.
> **Base:** `frontend/src/features/editor/ArchitectureEditor.tsx`, `ComponentIcon.tsx`, `BehaviorEditorV41.tsx`, `Playback.tsx` e [UI-V6-001](UI-V6-001.md).

## 1. Paleta e canvas

- Remover `DATABASE` do catálogo de criação e do drag-and-drop. Não excluir o código legado de importação até validar a migração.
- Categorias visuais propostas: **Databases** (oito tipos) e **Data Processing** (sete). Exibir inicialmente apenas tipos P0 executáveis; P1/P2 permanecem documentados até terem capacidade validada.
- Usar o mapa Lucide de `UI-V6-001` em paleta, canvas, seletor de tipo e editor contextual; ícone não determina semântica.
- Continuar com React Flow, zoom, seleção, arrastar, conectar, editar e excluir; sem editor paralelo de arquiteturas.

## 2. Painel de propriedades contextual

| Tipo | Campos P0 essenciais |
| --- | --- |
| Relational | Registros iniciais, tamanho médio, latências read/write, pool, concorrência e fila |
| Document | Dataset/coleção, atributos habilitados para filtro, limites e perfil de custo |
| Key-Value | Quantidade inicial de chaves, tamanhos, custo GET/PUT e limites |
| ETL Pipeline | Fonte, destino, batch size, plano de etapas, limite de lotes |
| Data Transformer | Operações declarativas, custo por registro e política de rejeição |

Campos específicos de transações/índices/graph/time-series não aparecerão como implementados enquanto P1/P2 não estiver pronto. Valores de default devem ser idênticos no frontend, no validador e no contrato.

## 3. Editor de Actions

Manter o editor de `Behavior` atual; adicionar ações `DB_SELECT`, `DB_INSERT`, `DB_UPDATE`, `DB_DELETE`, `DB_GET`, `DB_PUT`, `DB_FIND`, `DB_BULK_INSERT`, `ETL_EXTRACT`, `ETL_TRANSFORM` e `ETL_LOAD` conforme capacidades aprovadas.

Fluxo recomendado:
1. Usuário seleciona o Service/ETL de origem e a Action.
2. UI lista somente conexões dirigidas válidas para o tipo de destino.
3. Exibe parâmetros específicos, limites e referências `dependsOn`/`outputRef`.
4. A validação local dá feedback imediato; o backend é autoridade final.
5. Timeline evidencia operação, recurso, estado, bytes, volume e duração.

Evitar campo de SQL ou JSON genérico como interface principal: preferir inputs estruturados e filtros restritos. Se houver JSON avançado, erro de sintaxe nunca deve aplicar estado parcial ao modelo.

## 4. Importação e migração

A importação JSON da v0.5 valida uma cópia antes de substituir o canvas. Preservar esse comportamento.

- Detectar nós com `type: DATABASE` e informar IDs, conexões e propriedades associadas.
- Exibir uma **prévia de conversão** com sugestão `RELATIONAL_DATABASE` somente onde houver equivalência; permitir escolha de destino compatível quando ambíguo.
- Validar arquitetura **e cenário completo quando presente**, além da validação atual que aceita somente objeto `components/connections`; não prometer importação de SimulationRequest antes de implementá-la.
- Não aplicar conversão sem confirmação. Falha/cancelamento deixa o canvas original intocado.
- Exportação/download ainda não disponível na v0.5: prever tarefa separada de export JSON canônico para permitir round-trip explícito, com testes.

## 5. Playback e resultados

Reutilizar `Playback.tsx`, timeline, trace e resultados; acrescentar apresentação de `dataOutcomes` sem sobrescrever `resourceOutcomes`.

Painel de inspeção proposto para uma Action: `actionId`, `resourceComponentId`, `resultCode`, timestamps, espera, tempo de execução, lidos/escritos/rejeitados e bytes. Link causal para parent operation. Exibir `SKIPPED` de LOAD quando TRANSFORM falhou. Não inferir sucesso apenas por ausência de erro.

## 6. Acessibilidade e consistência

- Labels textuais obrigatórias, `aria-hidden` em SVG decorativos, contraste nos dois temas, foco visível e erros associados ao campo.
- Ícones e nomes distintos em zoom reduzido; sem dependência exclusiva de cor.
- UI mostra mensagens de migração por componente e lista erros de validação acionáveis.
- Testar teclado, seleção, drag-and-drop, edição e ausência do tipo `DATABASE` na paleta.
